# Plan: Live ACP Logs Panel

## Goal
Connect the Devin ACP trace log on disk to the JheckBot conversation UI, streaming live log lines over the existing SSE channel and rendering them in a collapsible panel.

## Implementation Order

### 1. Locate and follow the active ACP log
- Identify Devin CLI log directory (`~/.local/share/devin/cli/logs/`).
- Determine log file naming: `devin_YYYYMMDD-HHMMSS_<pid>.log`.
- Observe that the meaningful trace is written by the `devin acp` child process, not the tmux pane.

### 2. Backend log tailing
- Create `apps/api/src/agent/LogTailer.ts` that:
  - Resolves the tmux pane PID via `TmuxManager.getPanePid`.
  - Walks child processes in `/proc/<pid>/task/*/children`.
  - Identifies the `devin acp` child by reading `/proc/<pid>/cmdline`.
  - Picks the matching `devin_*_<pid>.log` file.
  - Tails new bytes, emits complete lines, buffers partial lines with `StringDecoder`, and recovers from log rotation.
- Add `TmuxManager.getPanePid` to query `tmux display-message -p '#{pane_pid}'`.
- Add `DevinAdapter.getLogDir` to resolve the Devin CLI log directory from the binary location.

### 3. Integrate with `AgentManager`
- Add a `logTailer` field to `ManagedAgentRun`.
- Create the tailer in `startWatcher` when a `TmuxManager` is present.
- In `captureAndAppend`, call `LogTailer.tail()` and append lines to `pendingLog`.
- Keep the existing raw-tmux fallback for tests and legacy paths.

### 4. Frontend panel
- Add `liveLog`, `logsOpen`, and `logsContainer` refs to `conversations/[id].vue`.
- Handle `log` SSE events: parse `data.content` and append to `liveLog` via `appendLog`.
- Add a toggle button inside the processing indicator and a `<pre>` log panel below it.
- Open the panel automatically on the first log event; cap total log length at 500k chars.
- Set `agentStarting = false` when a `log` event arrives so the live output card becomes visible.

### 5. Tests and validation
- Add `AgentManager` unit test that creates a temp log dir, writes to the log file after the tailer starts, and asserts `log` events are emitted.
- Run `pnpm -C apps/api typecheck` and `pnpm -C apps/web typecheck`.
- Run `pnpm -C apps/api test` and `pnpm -C apps/web test`.
- Validate live logs in a running conversation via Playwright MCP.

### 6. Documentation and QA
- Write spec (`docs/superpowers/specifications/20260826_040458-live-logs.md`).
- Write this plan.
- Write QA report (`docs/superpowers/qa/20260826_040458-live-logs.md`) and capture a screenshot.

## Risks and Mitigations
| Risk | Mitigation |
|------|-----------|
| `devin acp` child may not exist when tailer first resolves | Use pane PID as fallback and re-resolve each tick until the child appears. |
| Log files may rotate or be recreated | Reset position to current size and clear partial buffer on size decrease. |
| Sensitive data in trace logs | Render as escaped text; no secrets are parsed or highlighted. Conversation access is already gated by the existing SSE auth. |
| Large logs causing UI slowdown | Cap `liveLog` at 500k characters and keep it in a scrollable `<pre>`. |
