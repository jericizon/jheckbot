# Spec: Live ACP Logs Panel

## Objective
Show a live, streamable view of Devin ACP trace logs inside the conversation UI while an agent run is active. The feature addresses the problem where long-running agents in `--print` mode produce no visible tmux output and the UI appears frozen with only a generic "Processing" dot.

## Acceptance Criteria
- The backend discovers and tails the active `devin_*.log` file written by the `devin acp` child process.
- Log events are persisted as `agent_events` with `event_type = 'log'` and replayed through the existing SSE replay path.
- The frontend receives `log` SSE events and appends them to a live, bounded, auto-scrolling panel.
- A toggle lets the user collapse or expand the logs panel; the panel opens automatically when the first log line arrives.
- Log content is rendered as escaped text, never as raw HTML.
- Existing output and terminal status event behavior is preserved.
- All backend and frontend unit tests pass; typechecks pass.

## Event Contract
- SSE event name: `log`
- SSE data payload: `{"content": "<one or more log lines joined by \\n>"}`
- Persisted content: `JSON.stringify({ content })`

## Project Structure
- Log tailer: `apps/api/src/agent/LogTailer.ts`
- Agent runner integration: `apps/api/src/agent/AgentManager.ts`
- Tmux pane PID lookup: `apps/api/src/agent/TmuxManager.ts`
- Devin CLI log directory resolver: `apps/api/src/agent/DevinAdapter.ts`
- UI panel and handlers: `apps/web/app/pages/conversations/[id].vue`
- QA artifacts: `docs/qa-artifacts/20260826_040458_live-logs/`

## Code Style
- Tail logs in complete lines using `StringDecoder` and a partial-line buffer; avoid splitting multi-byte UTF-8 characters.
- Prefer per-run `LogTailer` instances that live with the `AgentManager` watcher and are re-created on retry.
- Treat Devin trace content as untrusted text; use Vue text interpolation, never `v-html`.

## Testing Strategy
- Unit test in `apps/api/tests/agent-manager.test.ts` covers tailing a real log file and emitting `log` events.
- Existing `sse-replay.test.ts` covers replay of `log` events through the SSE endpoint.
- Manual live-browser validation confirms the panel updates in real time while the active agent runs.

## Boundaries
- **Always:** run `pnpm -C apps/api test`, `pnpm -C apps/web test`, and workspace typechecks before committing.
- **Ask first:** changing the SSE event schema beyond adding the `log` type, adding new dependencies.
- **Never:** expose credentials, tokens, or stack traces in log content or UI; commit binary/artifact files without QA justification.
